## ⚠️ Найденные слабые стороны

### Закрыты

1. **Нет единой точки управления** — всё делалось ad-hoc скриптами.
   → Добавлен `farm.py` (doctor/reg/import/keys/parse/crawl) — единый CLI.
2. **Нет конфига** — почта/капча/прокси хардкодились в .env апстрима.
   → Добавлен `config/farm.config.example.json`: 7 email-провайдеров, 2 режима капчи (free_browser/yescaptcha fallback), 3 режима прокси (direct/single/pool) с geo-whitelist.
3. **Нет health-check** — смерть шлюза/аккаунтов обнаруживалась только по 502.
   → `farm.py doctor`: gateway, egress geo, пул, модели, inference probe. ALL OK / HAS FAILURES.
4. **Windows не поддерживался setup-скриптом** (только bash).
   → `gateway/setup_windows.bat` + `gen_secrets.ps1` (секреты без openssl).
5. **replenish.py хардкодил пути машины Влада** → генерализован под env (REG_DIR/G2A_BASE/SECRETS_FILE).
6. **Нет верификации урожая** — модель могла выдумать посты.
   → В crawl встроен сэмплинг через fxtwitter. **v2 (21.09)**: сэмпл случайный (убран фиксированный seed), проверяется не только существование твита, но и совпадение даты и близость лайков (лайки только растут: parsed ≤ live в толерансе 30%+3). Итог: `exists N/N, date-match N/N, likes-close N/N`.
7. **doctor-баг**: гео-чек сравнивал полное имя страны ("Ukraine") с кодами whitelist → всегда WARN. Исправлен на countryCode. Пруф: было WARN при живой UA, стало OK.
11. **Нет дедупликации между прогона crawl** — tweets.json перезаписывался; для непрерывного мониторинга нужен state-файл seen-идишников.
    → **Закрыто v2 (21.09)**: `farm.py crawl --state seen.json` — seen-state по tweet_id: загружается до прогона (прошлые id сразу в seen), мержится после, output содержит все прогоны; запись атомарная (.tmp + os.replace). Покрыто офлайн-тестом `tests/test_parser_offline.py` (roundtrip, идемпотентность, битый файл).
14. **Парсер доверял датам модели** — 1/105 постов оказался старше 14-дневного окна.
    → **Закрыто v2 (21.09)**: пост-фильтр `date_within` до дедупа: 9 форматов дат (+ unix ts), грейс ±1 день на TZ-дрейф, нечитаемые даты НЕ дропаются (логируются), `--days 0` отключает фильтр. Задержка между запросами больше не заимствует `farm.delay_between_accounts_sec` — отдельный ключ `parser.delay_between_queries_sec`.

### Остаются открытыми (честно)

8. **X фильтрует откровенно серые темы**: 'cvv shop', 'proxy seller telegram', 'account selling' → 0 результатов (3/13 запросов). Ограничение апстрим-модели, не баг парсера. Обход: нейтральные формулировки запросов, англ. термины.
9. **Нет мониторинга бан-вейва**: xAI банит акки волнами; пул может осыпаться за день. Нужен cron `farm.py doctor` + алерт при web-пуле < N. (Cron-обёртка не написана — TODO.)
10. **Один IP на весь пул**: все акки регятся и работают с одного выхода → коррелируемый след. При масштабировании >20 акков нужен residential-пул с ротацией на аккаунт (grok2api это умеет: egress scopes + `{account}` lease, не настроено).
12. **Web-квота grok-chat-fast конечна** — при исчерпании шлюз ротит на следующий акк, но при пустом пуле парсинг встанет. Авто-репленiш по порогу квоты не реализован.
13. **CPA/OAuth Device Flow не автоматизирован для Build-пула** — конверсия Web→Build работает через admin API, но отдельный Build device-flow (`grok login --device-auth`) остаётся ручным.

15. **replenish.py не кроссплатформенный**: `.venv\Scripts\python.exe` (Windows-only) и дефолт REG_DIR на каталог автора зашиты в код; doctor не проверяет Build-пул отдельно от Web.
